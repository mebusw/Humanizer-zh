# 角色目录

本目录存放**角色目录**：**一个角色一个目录**，目录内含该角色的角色卡、量化画像与原始语料。

```
roles/
├── README.md          ← 本文件：角色目录索引
└── 申导/
    ├── README.md      ← 角色卡（该角色的入口）
    ├── 风格画像.md    ← 量化画像（证据层）
    └── 语料/
        ├── README.md  ← 语料清单
        ├── A档-现场口语/
        └── B档-演讲实录/
```

角色卡针对某位具体作者的说话与写作特征。

角色卡回答"**这个人怎么说**"，不回答"**这个人说什么**"。它不提供事实、数字、案例、经历或立场；这些仍然只能来自待编辑文本或用户提供的材料。角色卡与 SKILL.md 的 31 个检查点配合使用：检查点指出"哪里有毛病"，角色卡指出"这个人本来会怎么写"。

## 使用规则

1. **先确定语域。** 同一作者的口语与书面成稿差异很大。角色卡会标注各语域的基线，编辑前先确认目标文本属于哪一档；语域尚未取样时，按输入文本自身的语域处理，不要硬套。
2. **角色卡是候选，不是强制。** 目标文本已经通顺的地方保持不变。角色卡用来在两三个都成立的写法中挑"更像这个作者"的那一个，或在文本明显不像他时指出差距。
3. **事实优先级高于风格。** 角色卡中的任何句式、词频都不能用来给原文补造信息，也不能把原文的"可能"改写成角色卡风格的"确定"。
4. **不能凭角色卡判断作者身份。** 风格相似不等于同一个人所写，也不构成任何来源证据。
5. **一次只加载一个角色。** 混用多个角色卡会互相抵消特征，得到"不像任何人"的文本。

## 载入方式

用户点名角色时（例如"用申导的口吻改写"），先读该角色目录下的 `README.md`（角色卡），需要核对统计口径或补充语料时再看 `风格画像.md` 与 `语料清单.md`，最后按 SKILL.md 的工作流程执行。未点名时不要主动套用任何角色卡。

**语料不进入版本库。** `roles/*/语料/` 存放原始授课转写稿，含客户与学员的可识别信息；角色目录所在的仓库为公开仓库，这些文件已加入 `.gitignore`，不会被提交或推送。需要备份时请另行同步到私有位置。
